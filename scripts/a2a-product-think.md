# /product-thinker — A2A Network: Переосмысление «Кто свободен?» и «Найти человека»

## Контекст

Neva Messenger — это мессенджер с AI-агентами, которые помогают пользователю управлять отношениями. У нас есть две A2A (agent-to-agent) функции:

### Текущее состояние «Кто свободен?»
- Кнопка на экране Relationships
- Пользователь вводит контекст ("Сегодня вечером", "В субботу днём")
- Система рассылает запрос агентам всех друзей (relationship level = friend/close)
- Агент каждого друга решает сам (по правилам автономии): ответить автоматически (на основе контекста из переписки + настроения + целей) или спросить друга
- Результаты стримятся через WebSocket
- **Проблема:** Нет UI для отображения агрегированных результатов. Пользователь нажимает кнопку и... ничего не видит

### Текущее состояние «Найти человека»
- Открывает NetworkSheet с формой создания Need/Offer
- Needs (запросы): "Ищу React-разработчика" с категорией, срочностью, видимостью
- Offers (предложения): "Делаю логотипы"
- Matching через embeddings similarity + trust score + social distance
- Consent flow через agent dialogs
- **Проблема:** Работает как доска объявлений. Нет социального контекста, не понятно зачем. Friction высокий — нужно заполнить форму

### Что уже работает хорошо
- Agent Dialog система (диалоги между агентами, автономия, smart context analysis)
- Embedding-based matching с trust scoring
- WebSocket real-time обновления
- Autonomy rules (auto-approve для close friends, ask user для acquaintances)
- Contact Intelligence (persona, mood, memory, style per contact)

### Существующая база данных
- `contact_intelligence` — persona, mood, style per contact
- `contact_memory` — факты о контактах (день рождения, работа, интересы)
- `user_goals` — цели пользователя per chat
- `needs` / `offers` / `matches` — сетевой matching
- `agent_dialogs` — A2A коммуникация
- `proactive_actions` — nudges/предложения

## Задачи

### 1. Переосмыслить «Кто свободен?»
Текущая реализация — это broadcast-запрос "ты свободен?" всем друзьям. Подумай:
- Какие реальные сценарии стоят за этим? (пойти в бар, вызвать на помощь, найти компанию в поездку, пригласить на ужин)
- Как сделать это social-first, а не utility-first?
- Как показать результаты красиво и полезно?
- Как учесть контекст (вечером vs сейчас, 2 человека vs большая компания)?
- Как использовать AI-агентов для обогащения (агент знает что Маша сейчас грустит → подсказка "Маша может обрадоваться приглашению")
- Как не быть спамом для получателей?

### 2. Переосмыслить «Найти человека»
Текущая реализация — это LinkedIn-like needs/offers board. Подумай:
- Какие уникальные возможности даёт то, что это мессенджер (а не LinkedIn)?
- Как использовать knowledge graph и memory для smart matching?
- Как сделать matching organic (встроенным в разговоры), а не отдельной фичей?
- Примеры: "Мне нужен дизайнер" → агент знает, что друг Коля делает дизайн, и предлагает познакомить
- Как обеспечить privacy и consent при этом?
- Как агенты могут проактивно предлагать connections?

### 3. Придумать новые A2A сценарии
Помимо "свободен?" и "найди человека", какие ещё agent-to-agent взаимодействия ценны:
- Совместное планирование (голосования, выбор ресторана)
- Group coordination (собрать группу на мероприятие)
- Care chains (друг грустит → агент предлагает другим друзьям написать)
- Knowledge sharing (кто-то спрашивает совет → агент знает эксперта)
- Gifting intelligence (ДР через неделю → агент координирует подарок)

### 4. Составить Product Vision
Сформулируй:
- **Value proposition** для A2A в мессенджере (1-2 предложения)
- **User stories** (10-15 штук, формат "Как [кто], я хочу [что], чтобы [зачем]")
- **Feature priority matrix** (impact vs effort, must-have vs nice-to-have)
- **MVP scope** — что делать ПЕРВЫМ (минимально ценный набор на 1-2 недели)
- **Anti-patterns** — чего точно НЕ делать (спам, creepy suggestions, privacy violations)
